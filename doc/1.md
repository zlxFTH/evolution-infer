## 数据格式

复制区间的格式为 $(i, l, r)$ 三元组，表示生成 token 序列第 $i$ 个下标的时候，**可以直接**复制 $[l, r)$ 区间（左闭右开）。为了数据简洁，这里只存**极长区间**，$(i, l, r)$ 三元组信息蕴含了 $i + 1$ 可以复制 $[l + 1, r)$，不保存 $(i +1, l + 1, r)$。

下标统一采用 0-index。

上下文采用拼接方式，按照 `prompt -> cot -> output` 的顺序拼接。

+ 生成 cot 序列的第 $i$ 个 token 时，可见上下文为 `[0, len(prompt) + i)`

+ 生成 output 序列的第 $i$ 个 token 时，可见上下文为 `[0, len(prompt) + len(cot) + i)`

数据保存为 `.jsonl` 格式，字段如下

+ `id`：数据编号
+ `prompt`：提示词
+ `cot`：思维链
+ `output`：模型输出
+ `prompt_ids`：提示词 token 序列
+ `cot_ids`：思维链 token 序列
+ `output_ids`：模型输出 token 序列
+ `copy_cot`：生成 cot 的时候，模型应该进行 copy 的位置
+ `copy_output`：生成 output 的时候，模型应该进行 copy 的位置

例子

```json
{
  "id": "sample_0001",
  "prompt": "原代码与修改指令文本",
  "cot": "思考过程文本（关 CoT 时为空串）",
  "output": "模型输出文本",
  "prompt_ids": [151644, 872, 198],
  "cot_ids": [101, 102, 103],
  "output_ids": [201, 202, 151645],
  "copy_cot": [[10, 2, 18]],
  "copy_output": [[0, 18, 95], [112, 460, 488]]
}
```

### 注 1

$r - l\le 2$ **一定不优**，上一次前向已经能预测出下一个 token，copy locator 还需要做一次并行验证，效率严格不如直接自回归。

令 $k$ 为强制最小复制长度，所有数据必须满足 $r - l \ge k$，设计阶段令 $k = 5$，最后根据实际测试选择合理阈值。

### 注 2

每个下标 $i$，**钦定最多有一个可复制区间**。意思是，考虑 $[l_1, r_1)$ 对应到生成的序列下标是 $[i_1, j_1]$，那么让数据里 $[i_1, j_1]$ 和 $[i_2, j_2]$ 两两不交。

这样设计，是因为人类不会先从上文复制一段，删一段后缀，再复制另外一段。希望模型能学到这个能力。

### 注 3

假设现在确定了每个 $i$ 往后复制的长度 $len$，上文有多个 $[l, r)$ 可供复制如何选择？

见后文每个 Dataset 的说明。

## Dataset: CopyGen

Related Work: CopyGen 使用的数据集。使用这个数据集来和最相关的工作进行性能数据比较。

### 数据信息说明

CopyGen 数据集包含代码（code）、法律合同（contract）、学术文献（literature）、随机 token 序列（random_sequence）四个领域。每个领域都有 `train` 和 `test` 两部分。

它的每条样本都要求模型在很长的上下文里，把指定片段一字不差地原样输出（只有 `code` 会在输出开头附带一句简短的 `Explanation:`，其余三域均为纯复制，且 `contract` 还会出现输出段落间的自复制）。

因为输出里绝大部分 token 都能直接照抄前文，它非常适合用来检验无损投机复制方案在 Exact Match 准确率 与生成速度上的表现。

> Exact Match：最终输出（不含 CoT）与标准答案严格一致计 `1`，否则计 `0`。`contract`、`literature`、`random_sequence` 要求规范化空白后全串匹配 `gold_answer`；`code` 按锚点提取目标代码块，要求 Python 词法序列完全匹配 `gold_evidence`。`gold_answer` 和  `gold_evidence` 原数据集有，计算 Exact Match 的代码和原作统一。

### copy_output

CopyGen 里能复制的区间比较长，每发起一次复制都要做一次并行验证。一方面希望复制的 token 尽可能多，另一方面希望能一把复制的长区间尽量保持完整。

长区间的前后还有可能匹配上换行、代码围栏等符号。如果只看总复制长度，原本能一把复制的 380 个 token，可能会拆成 379 和 3 两段。后一段把最后一个代码 token 和两个围栏 token 一起复制，总共多复制了两个 token，也多做了一次验证。

但这种零散 token 本身用 DSpark 投机解码做一次并行极易通过，不适合纳入复制区间。

这里我选择做一个 trade-off，每发起一次复制扣掉固定的成本 $c$。考虑从后往前进行 DP，设 $f(i)$ 表示从输出下标 $i$ 开始能得到的最大净收益。

$$
f(i) = \max\left\{f(i+1),\ \max_{j-i \ge k \land \mathrm{copy}(i,j)} \big(f(j) + j-i-c\big)\right\}, \qquad f(n) = 0
$$

$n$ 是参与匹配的输出长度，$\mathrm{copy}(i,j)$ 表示 $[i,j)$ 能在当前可见的上文里找到完全相同的 token 序列。

目前令 $k=5$，每段至少复制 5 个 token。令 $c=5$，每多发起一次复制扣 5 分。总收益相同时，选复制次数更少的方案。按照当前方案，原数据集的长区间均能复制，整个数据集只少复制了 5 个换行 token。

### 上文区间选择

> 数据格式 > 注 3：假设现在确定了每个 $i$ 往后复制的长度 $len$，上文有多个 $[l, r)$ 如何选择？

按照优先级从前往后，

+ 源头优先，优先从 `prompt` 里抄，其次从 `cot` 里抄。
  + 开关 CoT 可以共用一套数据；CoT 里面多次复述指向同一个区间，把复制能力的语义聚集在一个地方更能学好；CoT 比较发散，有很多噪声信息，分块时信息不佳。
+ 看 $l$ 左侧和 $i$ 左侧的最长公共匹配长度，长的优先。
  + 推理的时候和 $\ln(1 + \text{overlap})$ 特征一致（让 model 学习左侧已匹配重合长度如何参与决策），这样设计避免梯度冲突。
+ 如果上面两条还打平，选择最靠后的。
  + 候选在 `prompt`，这个数据集无所谓。
  + 候选在 `cot`，选择最靠后的（越靠后的越倾向于结论，前面的可能有错误信息）


### 训练

random_sequence 是同质化的机械复制，对于 CoT 而言又没有逻辑，`Train` 里面占比又很高，这类数据学多了效果反而不好。

经过测试训练，只训 code，一条 random_sequence 都不训，在 random_sequence 测试集上草稿接受率就已经达到 $93.2\%$。最终训练应当压低 random_sequence 的训练占比。
